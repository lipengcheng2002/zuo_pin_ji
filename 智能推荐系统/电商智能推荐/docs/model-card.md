# 模型卡 · ZHIYAN Retrieval & Ranking

## 1. 模型概览

| 项目 | 内容 |
| --- | --- |
| 模型名称 | ZHIYAN reco-agent-2.3（在线）/ two-tower + LightGBM（离线） |
| 任务 | 服装商品召回与个性化排序 |
| 在线回退编码器 | `hash-tfidf-v2`，256 维确定性特征哈希 |
| 离线召回 | 双塔（用户/商品），64 维输出，in-batch softmax |
| 离线排序 | LightGBM binary ranker（20 特征），可切换 LambdaRank |
| 训练数据 | 合成 160 用户 / 40 商品 / 2,105 条行为 / 4,000 条排序候选 |
| 评估日期 | 2026-10-29（产物生成时间见 `offline-eval.json`） |

## 2. 数据来源与偏差

**重要：当前仓库内所有用户、商品与行为均为合成数据，仅用于演示系统闭环。**

- 商品：40 个时尚品类，风格标签、价格、评分、库存随机生成
- 用户：160 个画像，含 6 维隐向量、风格偏好、价格中心、活跃度
- 行为：基于隐向量 + 风格重叠 + 价格惩罚 + 噪声采样
- 排序特征：基于同一信号 + 高斯噪声生成，标签按 logistic 采样

因此离线指标**高于真实电商场景**，不能作为生产效果承诺。真实部署必须用自有数据重训并做时间切分评估。

合成数据包含的已知偏差：

- 用户兴趣与商品隐向量同源，模型容易学到「过强」的偏好
- 商品数量只有 40，覆盖率容易接近 100%
- 缺少冷启动用户、季节性漂移、退款/退货负反馈、曝光偏差
- 没有真实价格促销、库存约束、流量分配机制

## 3. 离线评估结果（合成数据）

最近一次 `python ml/scripts/simulate_pipeline.py` 产物：

| 指标 | 数值 | 解释 |
| --- | --- | --- |
| AUC | 0.881 | 正负样本对排序能力（乐观） |
| Precision@10 | 0.113 | 每位用户 Top10 命中率；因单用户正样本少而偏低 |
| Recall@10 | 0.875 | 测试正样本被 Top10 覆盖的比例 |
| NDCG@10 | 0.885 | 考虑位置的排序质量 |

| Test users | 84 | 有测试正样本的用户数 |

生产脚本（`ml/train/two_tower.py`）会在真实 CSV 上使用相同接口输出 `metrics.json`；`ml/eval/offline_eval.py` 计算同一组指标。

## 4. 训练方法

### 双塔（`ml/train/two_tower.py`）

- 用户塔 / 商品塔：Embedding(hidden=128) → Linear → GELU → LayerNorm → Linear(64) → L2 normalize
- 训练：in-batch softmax，温度可学习，AdamW + cosine scheduler，梯度裁剪
- 正样本来自行为，权重 purchase 8 / cart 5 / wishlist 3.5 / click 2 / view 1
- 负样本为同 batch 其他商品（隐式负采样）
- 时间切分：按时间排序取最后 20% 作为测试
- 评估：AUC（随机负样本）、Precision/Recall/NDCG@10、Coverage、Novelty

### 排序（`ml/train/rank_lgbm.py`）

- 输入：候选级特征（画像亲和、语义、协同、约束、趋势、质量、互补、价格、时效、毛利、CTR/CVR、用户 RFM、品类/颜色/风格/场景匹配、库存）
- 目标：二分类点击/购买标签
- 训练：LightGBM，early stopping，group 切分避免用户泄漏
- 输出：`model.txt`、特征重要度、AUC/Precision@10

### 特征（`ml/spark/feature_engineering.py`）

- 用户：30 天事件数、购买/加购/收藏、金额、最近活跃、会话数、Top 风格/品类、衰减
- 商品：曝光、点击、加购、购买、CTR/CVR、近 7 日趋势、质量分、库存
- 共现：同 session 商品对，截断 Top-20 邻居
- 输出 Parquet + `summary.json`

## 5. 在线与离线一致性

在线服务使用同一套字段语义与权重接口：

- 在线 `getFeatureStore()` 从事件实时计算
- 离线 Spark 产出写到特征库；上线前应做「离线/在线特征一致性」校验（均值、缺失率、分位）
- 在线 fallback 编码器与双塔向量不在同一空间；生产接入时需：
  1. 导出 item/user embedding
  2. 统一维度与归一化
  3. 建立 ANN 索引
  4. 保留 `recall()` 的 `vector` 源接口
  5. 用 A/B 验证替换收益与延迟

## 6. 预期用途

- 服装类电商首页、详情页搭配、购物袋交叉、搜索排序与 AI 造型师
- 需要「可解释推荐理由」的场景：每件商品附带证据与置信度
- 运营分析：召回贡献、场景权重、实验与护栏

## 7. 非预期用途

- 医疗、金融、信贷等高风险决策
- 对未成年人进行个性化营销
- 以性别、年龄、地域等敏感属性做差别定价或歧视性排序
- 用 AI 生成的价格/库存/政策声明替代真实业务系统

## 8. 公平性与安全

- 当前画像包含性别与年龄字段，但未用于排序打分；仅用于商品尺码与内容适配
- 生产部署应移除敏感属性或做偏差审计（覆盖率、曝光均等、价格一致性）
- 推荐理由必须可核对；护栏阻止价格、库存、政策的无依据陈述
- LLM 模式下的输出会经过价格事实、绝对化用语与尺码免责校验

## 9. 局限与后续

1. 合成数据导致指标乐观；需真实数据重训
2. 未处理曝光偏差、位置偏差、退款反馈
3. 在线精确 cosine 仅适合小目录；大规模需 ANN
4. 排序器未做在线学习；权重目前由配置与离线校准共同决定
5. 多目标（转化、满意度、毛利、退货）目前以加权与护栏近似，未做帕累托优化
6. 缺少因果推断；A/B 结论仅适用于当前流量结构
