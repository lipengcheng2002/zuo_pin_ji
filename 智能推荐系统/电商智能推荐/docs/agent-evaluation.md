# 智能体评测基线

> 目标：把“回答看起来还行”变成可重复的回归门禁。评测不依赖 Web、模型 Key 或数据库，CI 可在无外部服务时运行。

## 1. 运行

```bash
npm run eval:agent    # 仅评测套件，verbose 输出基线
npm run test:agent    # Agent + 引擎全部单测
npm run test          # 全项目单测
```

评测代码：`src/lib/agent/evaluation.ts`（指标计算）与 `src/lib/agent/evaluation.test.ts`（金标案例与阈值）。

## 2. 当前基线（2026-10）

| 维度 | 结果 | 阈值 | 说明 |
| --- | --- | --- | --- |
| 意图识别 | 33/33 · 100% | ≥ 95% | 11 类意图金标 |
| 槽位抽取 | 13/13 · 100% | ≥ 90% | 预算/品类/颜色/场合/尺码/订单号/商品指代 |

| 检索 MRR | 1.000 | ≥ 0.85 | 排序质量 |
| 注入拦截 | 15/15 · 100% | 100% | 中英文越权/泄密语料 |
| 正常问题误伤 | 0/10 | 0 | 购物/政策/尺码问题 |

阈值写在 `evaluation.test.ts`；修改阈值必须在 PR 说明理由。

## 3. 覆盖范围

- **意图**：造型、找货、尺码、对比、商品问答、政策、订单、购物袋、偏好更新、问候、寒暄。
- **槽位**：中文预算（含数字区间）、品类、颜色、场合、尺码、订单号、商品短名/别名。
- **RAG**：配送、退换、养护、会员、优惠券、发票、可持续、AI 透明度、尺码。
- **安全**：提示词注入、系统提示/密钥窃取、角色越权、开发者模式、正常问题误伤。
- **既有单测**：召回五路、理由证据、预算/库存约束、护栏价格事实、密码哈希、库存承诺、会员会话。

## 4. 如何扩展

1. 在 `evaluation.test.ts` 的 `INTENT_CASES` 添加真实脱敏问法，标注意图与必要槽位。
2. 在 `RETRIEVAL_CASES` 添加“问题 → 期望 policy id”；policy id 见 `src/lib/engine/knowledge.ts`。
3. 在 `INJECTION_CASES` / `BENIGN_CASES` 添加攻击与正常问法；正常问法用于防误伤。
4. 运行 `npm run eval:agent`，失败时先修规则/检索/Prompt，不要先降阈值。
5. 真实模型接入后，增加线上抽样集与人工标注；LLM 路径应单独统计 groundedness、事实错误率与 P95。

## 5. 发布门禁

- `npm run test:agent` 必须通过。
- 注入拦截率必须 100%，正常问题误伤必须为 0。
- 意图或检索低于阈值不得发布；Prompt 变更需附评测 diff。
- `promptVersion`、模型名、capabilities 快照与镜像 digest 一起进入变更单。
- 线上观察 `zhiyan_agent_latency_p95_ms`、`zhiyan_agent_guardrail_hits_total`、负反馈率；异常时可用 `AGENT_ENABLED=false` 熔断。
